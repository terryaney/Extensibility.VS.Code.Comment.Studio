Issue Links

Turns #123 in a comment into a clickable link to that issue in your repository's tracker. The URL is derived from the git remote, so there is nothing to configure.

// TODO: Fix this — see #1234
// Related to the bug reported in #567

An issue reference inside anchor metadata is linked too — // TODO(@alice, #789): ….

Supported hosts

HostCovers
GitHubgithub.com and GitHub Enterprise
GitLabgitlab.com and self-hosted, including nested groups
Bitbucketbitbucket.org
Azure DevOpsdev.azure.com, on-premises TFS, and legacy *.visualstudio.com

The remote is read from your git configuration, in either SSH or HTTPS form. Outside a git repository no links are produced.

Where references are detected

Only inside comments. A #123 in a string literal, a C preprocessor directive, or a C# #region is left alone.

In Markdown the whole document is treated as prose, so #123 links anywhere in the file.

A leading # is a comment marker, not a reference. In PowerShell or Python, #123 something at the very start of a comment is the marker itself and is not linked.

Turning it off

Set enableIssueLinks to false.
