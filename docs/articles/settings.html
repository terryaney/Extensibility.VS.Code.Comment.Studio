Settings Reference

Every setting the extension contributes. All are prefixed kat-comment-studio. and can be set per user or per workspace.

Rendering

SettingTypeDefaultDescription
xmlCommentRenderingbooleantrueEnable XML comment rendering — CodeLens summary, auto-fold, and comment opacity.
xmlCommentOpacityinteger40Opacity percentage (0–100) for the dimmed original comment. 0 is fully invisible, 100 is no dimming.
codeLensSummaryTruncationnumber205Maximum characters in the CodeLens summary. 0 disables truncation. The popup always shows everything.
collapseXmlWhenRenderingOffbooleanfalseFold XML comments when a file opens, while rendering is off.
interceptF1ForCommentsbooleantruePress F1 in or below a doc comment to show the KAT tooltip instead of the VS Code help menu. See F1 interception.

Reflow

SettingTypeDefaultDescription
reflowLineLengthnumber120Maximum line width for reflow. Overridden by max_line_length in .editorconfig.
enableReflowOnCommentExitbooleantrueReflow a block when the caret leaves it after an edit.
enableReflowOnPastebooleantrueReflow a block after pasting into it.
autoExpandDelaynumber500Milliseconds before a folded comment expands once the caret enters it.
autoCollapseDelaynumber1000Milliseconds before an expanded comment re-collapses once the caret leaves. Also delays the exit-reflow by the same amount.

Pattern processing

patternProcessing is an object with four keys. Override only the ones you want — the rest keep their defaults.

"kat-comment-studio.patternProcessing": {
  "customTags": "PERF, SECURITY",
  "fileExtensions": "cs, ts, vb"
}
KeyDefaultDescription
customTags empty Extra anchor tags, colored Goldenrod and listed alongside the built-ins.
fileExtensions cs, vb, fs, cpp, c, h, ts, tsx, js, jsx, razor, cshtml, sql, ps1, psm1, md Extensions included in the workspace anchor scan and in LINK: validation.
ignoreFolders node_modules, bin, obj, .git, dist, out, build, .vs, .vscode-test Folder names excluded from the scan.
tagPrefixes @, $ Prefix characters recognized before a tag, so @TODO is treated as TODO.
fileExtensions does not gate inline coloring. It controls the workspace scan and link validation. Anchor coloring, prefix highlighting, issue links and LINK: run in every open file regardless.

What you cannot configure

The languages that receive CodeLens, documentation popups, folding and reflow are fixed — they are the ones with a known doc-comment style, listed in Supported languages. There is no setting to add one, because an unrecognized language has no comment style to parse and nothing would render.
