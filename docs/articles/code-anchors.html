Code Anchors

Tagged comments — TODO, HACK, BUG and your own — collected from the whole workspace into a tree and a sortable grid, with owners, issue references and due dates parsed out of the comment.

Matching rule

A word is treated as a tag when either of these is true:

  • It is written in exact uppercase — TODO, HACK, NOTE. A delimiter is optional, so // TODO fix this matches.
  • It carries a delimiter (: or !) or a metadata container attached with no space — // todo: fix this, // Todo! fix this, // todo(@alice) fix this.

Matched tags are normalized to uppercase everywhere, so todo: is displayed as TODO.

That two-part rule is what stops ordinary prose from lighting up. Neither word below is a tag — both are lowercase, mid-sentence, and carry no delimiter:

// Mid-review elections and a half-written note are not anchors.

All of these do match:

// TODO: Add input validation
// TODO Add input validation      — uppercase, so the colon is optional
// todo: also works               — normalized to TODO
// HACK! Temporary workaround until v2
// BUG: Off-by-one in edge case
// FIXME: This crashes on null input
// NOTE: This method is called from multiple threads
// ANCHOR(MyAnchor): navigation target
// LINK: ./services/Exporter.cs   — cross-file reference
Word boundaries are enforced. NOTES and x@TODO do not match — the tag must not be preceded or followed by a word character.
ANCHOR always needs a name. A bare // ANCHOR: is ignored entirely — it is not colorized and never appears in the tree or grid. Write // ANCHOR(MyName): ….
LINK always needs a delimiter and a target. A bare LINK word in prose is ignored, and so is an empty // LINK: — matching the LINK: navigation parser. Valid links appear in the tree and grid alongside the other anchors.

Metadata

Metadata goes in a container immediately after the tag. Separate multiple values with commas.

// TODO(@alice): Implement the export feature
// FIXME [#1234]: Known issue tracked in GitHub
// TODO(@bob, #456): Refactor this — owned by bob, tracked in issue 456
// TODO(2026-06-01): Remove this workaround after migration
// TODO(@alice, #789, 2026-03-15): Assigned, tracked, and due-dated
MetadataFormShown as
Owner@nameOwner column
Issue reference#123Issue column; also a clickable issue link
Due dateyyyy-MM-ddDue Date column; highlighted when overdue
Anchor namebare text, ANCHOR onlyTarget name for LINK: #Name
(…) and […] are interchangeable. Any metadata kind works in either container. TODO[@alice] and TODO(#123) are both valid.

Custom tags

Add your own tags with the customTags key of patternProcessing. They are colored Goldenrod (#DAA520) and appear in every view alongside the built-ins.

"kat-comment-studio.patternProcessing": {
  "customTags": "PERF, SECURITY, DEBT, REFACTOR"
}

Tag prefixes

If you sigil your tags so they are easier to grep for, configure the prefix characters and they are treated as part of the tag — including when coloring it.

// @TODO: treated exactly like TODO
// $HACK: works too

Set via the tagPrefixes key of patternProcessing (default "@, $"). Prefixes are stripped in the tree and grid, so @TODO is listed as TODO.

Not the same as an owner. A prefix sits before the tag (@TODO); an owner sits inside the metadata container (TODO(@alice)).

Where anchors are found

Two different mechanisms, with two different scopes:

MechanismScope
Inline coloring in the editor Every open file, regardless of language. Controlled by anchorColorizeMode.
Workspace scan feeding the tree, grid and status bar Files matching the fileExtensions key of patternProcessing, minus ignoreFolders.

So a tag in a file type outside fileExtensions still gets colored in the editor — it just is not collected into the views. Add the extension to fileExtensions to include it.

Markdown and prose files

In code, only text inside a comment is scanned. Markdown has no comment marker to look for — the whole document reads like a comment — so in .md and .markdown files every line is scanned instead.

TODO: plain prose lines match
- BUG: list items match
<!-- FIXME: HTML comments match -->

md is in the default fileExtensions, so Markdown is scanned out of the box. .vscode is not ignored, so anchors in notes and plan files under it are picked up — add it to ignoreFolders if you would rather they stayed out of the list.

Inline decorations

Each tag is colored inline with its type color, and a matching marker is drawn in the scrollbar / overview ruler so you can see anchor density at a glance.

Set anchorColorizeMode to never to turn all inline coloring off. The only other value is default.

Bottom panel grid

A sortable, filterable grid — KAT Comment Studio - Code Anchors — sits in the bottom panel beside Problems and Output.

Columns: Type · Description · File · Line · Owner · Issue · Due Date.

  • Click a header to sort ascending or descending
  • Free-text search filters across description, file, owner, repo and project
  • The type filter uses explicit include/exclude checkboxes and survives refresh and rescan
  • Drag column edges to resize; widths persist across reloads and restarts
  • Click a row to jump to the anchor; right-click a row to copy a row summary, or a cell to copy that value
  • Overdue due dates are highlighted

Open it with Focus on KAT Comment Studio - Code Anchors View, or by clicking the status bar badge.

Status bar badge

A badge in the status bar always shows N Anchors — the count after the current scope and type filter. It updates live as you scan, search or filter, and clicking it focuses the grid.

Until you open the Code Anchors panel for the first time the badge is highlighted. Set showAnchorCountBadges to false to suppress both the highlight and the sidebar count badge.

Navigation

Go to Next Anchor and Go to Previous Anchor move between anchors in the current file. Neither is bound by default — see suggested bindings.

Export

KAT Comment Studio: Export Code Anchors writes the currently visible anchors in CSV, Markdown or JSON.

Export opens an editor, it does not write a file. The result is placed in a new untitled editor with matching syntax highlighting. Save it yourself if you want it on disk.

CSV and Markdown share the column order Type, File, Line, Owner, Issue, Due Date, Description. JSON uses the same fields and additionally includes anchorName.

Scanning

With scanOnLoad at its default of true, the workspace is scanned when the extension activates. Results are cached and updated incrementally as you save files. Rescan at any time with KAT Comment Studio: Scan Code Anchors.

Anchor tags are configured through patternProcessing in VS Code settings. The custom_anchor_tags key in .editorconfig is parsed but not yet applied.
