LINK: Navigation

Write LINK: path/to/file.cs in a comment and it becomes a real reference — hover for a preview, Ctrl+Click to jump, and a warning squiggle when the target stops existing.

Path prefixes

PrefixResolves fromExample
@/Nearest .csproj directory@/Services/UserService.cs
/First workspace folder root/Core/Domain/src/Models/User.cs
./Current file's directory./Helpers/StringHelper.cs
../Current file's parent directory../Common/BaseEntity.cs
X:/, X:\Absolute Windows pathC:/BTR/Camelot/Core/src/User.cs
noneCurrent file's directoryModels/User.cs

Supported forms

// LINK: MyFile.cs                              bare, relative to this file's directory
// LINK: ./relative/path/to/file.cs             explicit relative
// LINK: ../sibling/folder/file.ts              parent-relative
// LINK: @/Services/UserService.cs              project-relative (nearest .csproj)
// LINK: /Core/Domain/src/Models/User.cs        workspace-root-relative (first folder)
// LINK: C:/BTR/Camelot/Core/src/User.cs        absolute
// LINK: MyFile.cs:42                           jump to line 42
// LINK: MyFile.cs:10-20                        select lines 10-20
// LINK: MyFile.cs#AnchorName                   jump to a named ANCHOR in that file
// LINK: #LocalAnchorInThisFile                 jump to an ANCHOR in this file
// LINK: path with spaces/file.cs:5             spaces are allowed

#AnchorName targets an ANCHOR anchor — // ANCHOR(AnchorName): ….

Editor behavior

ActionResult
HoverShows the resolved absolute path and whether the target exists
Type LINK: Path completions appear automatically. Picking a directory re-triggers suggestions so you can drill down without retyping. Named ANCHOR tags across the workspace are offered for LINK: #.
Ctrl+Click / F12Navigates to the target, at the requested line or anchor
Broken targetWarning squiggle; it clears as soon as the link resolves again

How the workspace shape affects resolution

  • / always resolves from the first workspace folder.
  • @/ resolves from the nearest .csproj directory above the file containing the link, falling back to the first workspace folder when there is no .csproj.

Multi-root workspace

@/ resolves per file — each source file uses its own nearest .csproj. / always uses the first folder listed in the .code-workspace.

// MyApp.code-workspace
{
  "folders": [
    { "path": "C:/BTR/Camelot/Core" },
    { "path": "C:/BTR/Camelot/UI" }
  ]
}

// File: C:/BTR/Camelot/Core/src/Domain/User.cs
//       (inside C:/BTR/Camelot/Core/src/Core.csproj)

// LINK: @/Services/UserService.cs
//   -> C:/BTR/Camelot/Core/src/Services/UserService.cs   (from Core.csproj)
// LINK: /Services/UserService.cs
//   -> C:/BTR/Camelot/Core/Services/UserService.cs       (from workspace folder 0)

A folder containing a .sln

There is no .sln parsing. VS Code treats the folder as the workspace root, and as long as source files sit inside a .csproj, @/ still resolves correctly.

// Opened: C:/BTR/Camelot/MyApp/          (folder containing MyApp.sln)
// File is under C:/BTR/Camelot/MyApp/src/Core/Core.csproj

// LINK: @/Services/UserService.cs
//   -> C:/BTR/Camelot/MyApp/src/Core/Services/UserService.cs
// LINK: /Core/Domain/User.cs
//   -> C:/BTR/Camelot/MyApp/Core/Domain/User.cs

A subfolder with no .csproj ancestor

// Opened: C:/BTR/Camelot/Core/Domain/    (no .csproj in the hierarchy)

// LINK: @/Models/User.cs  -> C:/BTR/Camelot/Core/Domain/Models/User.cs
// LINK: /Models/User.cs   -> same

Without a .csproj ancestor, @/ behaves exactly like /.

Link validation follows the scan settings. Targets are validated against the same fileExtensions list used by the anchor scan.
