Colors

Every color has theme-aware defaults for dark, light and high-contrast themes. Change them either with the colorOverrides setting or with VS Code's own workbench.colorCustomizations.

Two ways to override

// Extension setting — short keys, applies in every theme
"kat-comment-studio.colorOverrides": {
  "todo": "#FFA500",
  "prefixAlert": "#FF0000"
}

// VS Code setting — full theme color IDs, can be scoped per theme
"workbench.colorCustomizations": {
  "katCommentStudio.anchorTodo": "#FFA500"
}

Omit any key to keep its theme default.

Making the original comment invisible

Setting the opacity to zero hides the raw XML lines completely:

"kat-comment-studio.xmlCommentOpacity": 0

One blank line gap still remains after folding. That is the limit of what the VS Code extension API allows.

Styling code blocks in the popup

The documentation popup renders fenced code blocks through VS Code's internal Monaco tokenizer (monaco-tokenized-source). That path is not controlled by textCodeBlock.background or textPreformat.background — it inherits editorHoverWidget.background.

Inline code ticks

These are controlled by textCodeBlock.background. To match your editor background, run Developer: Generate Color Theme From Current Settings, copy the editor.background value, and set:

"workbench.colorCustomizations": {
  "textCodeBlock.background": "#222222"
}

That hex value is theme-specific and static — update it if you switch themes.

Fenced code blocks

No workbench color token affects these. The only way to style them is custom CSS through the Custom CSS and JS Loader extension.

This is a hack, and it has upkeep. Custom CSS patches the VS Code installation. You must re-run Enable Custom CSS and JS after every VS Code update, dismiss a “corrupted installation” warning each time, and update the hex color whenever you change themes.

Option A — scoped to KAT Comment Studio (recommended)

A CSS file, e.g. C:\Users\YourName\vscode-custom.css:

/* KAT Comment Studio — scoped fenced code block background */
.monaco-tokenized-source.kat-comment-hover {
    background-color: #222222 !important;   /* your editor.background */
    border: #ffffff 1px solid !important;
    padding: 5px !important;
    box-sizing: border-box !important;
}

And a JS file, e.g. C:\Users\YourName\vscode-custom.js. VS Code reuses one hover widget for every hover, so the script identifies KAT popups by a trailing five-space marker and tags them, growing the widget to fit the added padding:

const katObserver = new MutationObserver((mutations) => {
    const relevant = mutations.some(m =>
        m.target.closest?.('.monaco-hover') ||
        Array.from(m.addedNodes).some(n =>
            n.nodeType === 1 &&
            (n.classList?.contains('.monaco-hover') || n.querySelector?.('.monaco-hover'))
        )
    );

    if (!relevant) return;

    document.querySelectorAll('.monaco-hover .monaco-tokenized-source').forEach(h => {
        const isKat = h.querySelector('span:last-child')?.textContent?.slice(-5) === "     ";
        if (isKat) {
            const monacoHover = h.closest('.monaco-hover');
            if (monacoHover) {
                const updateStyle = (styleName, propertyName, current) => {
                    if (current) {
                        const newVal = parseFloat(current) + 12;
                        monacoHover.style[propertyName] = newVal + 'px';
                        monacoHover.querySelectorAll('[style*="' + styleName + ': ' + current + '"]').forEach(el => {
                            el.style[propertyName] = newVal + 'px';
                        });
                    }
                };
                updateStyle('height', 'height', monacoHover.style.height);
                updateStyle('max-height', 'maxHeight', monacoHover.style.maxHeight);
                updateStyle('width', 'width', monacoHover.style.width);
                updateStyle('max-width', 'maxWidth', monacoHover.style.maxWidth);
            }
            h.classList.add('kat-comment-hover');
        } else {
            h.classList.remove('kat-comment-hover');
        }
    });
});

katObserver.observe(document.body, { childList: true, subtree: true });

Register both files, then run Enable Custom CSS and JS and restart:

"vscode_custom_css.imports": [
    "file:///C:/Users/YourName/vscode-custom.css",
    "file:///C:/Users/YourName/vscode-custom.js"
]

On macOS and Linux use file:///home/yourname/… paths.

Option B — all Monaco hovers

No JS needed, but it restyles every VS Code hover tooltip, not just this extension's:

.monaco-hover .monaco-tokenized-source {
    background-color: #222222 !important;
}
