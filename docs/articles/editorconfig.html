EditorConfig

Reads .editorconfig so reflow line width can be set per project or per folder, in a file your whole team already shares.

[*.cs]
max_line_length = 100

Recognized keys

KeyEffect
max_line_lengthOverrides reflowLineLength for matching files. off is ignored.
custom_anchor_tagsParsed but not applied — see below
custom_anchor_tag_prefixesParsed but not applied — see below
Anchor tags cannot be set from .editorconfig yet. The two custom_anchor_tag* keys are read and understood, but nothing consumes them — only max_line_length reaches the extension's behavior. Configure anchor tags through the customTags and tagPrefixes keys of patternProcessing instead.

Resolution order

The extension walks up from the file's directory collecting .editorconfig files, and the closest one wins for each key. A file containing root = true stops the walk.

src/
  .editorconfig        max_line_length = 100        ← wins for files under src/
.editorconfig          root = true
                       max_line_length = 140

Section matching

The [...] header decides which files the keys beneath it apply to. Settings only take effect for files the header matches, so getting the glob right matters.

A glob containing / is matched against the file's path relative to the .editorconfig; one without a separator matches by file name in any subdirectory. A leading / anchors the pattern to the config's own directory.

PatternMatches
[*]Every file
[*.cs]Any .cs file, at any depth
[*.{cs,vb}]Any .cs or .vb file
[src/**/*.cs]Any .cs file under src/, including directly in it
[/build.cs]build.cs beside the config only, not in subfolders
[File[0-9].cs]File0.cs … File9.cs

Supported wildcards are **, *, ?, {a,b} alternation and [seq] / [!seq] character classes. Numeric {n..m} ranges are not supported. A section whose glob cannot be parsed is skipped rather than applied.

Live updates

A file watcher picks up .editorconfig changes immediately — no window reload.
