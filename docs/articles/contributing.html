Building the Extension

Everything needed to clone, run, test and package KAT Comment Studio. The same content lives in CONTRIBUTING.md.

Prerequisites

  • Node.js 20 or later
  • VS Code, any recent version
  • No global vsce — the repo uses a local @vscode/vsce dev dependency
git clone https://github.com/terryaney/Extensibility.VS.Code.Comment.Studio.git
cd Extensibility.VS.Code.Comment.Studio
npm install

Scripts

ScriptDoes
npm run compiletsc -p ./ — TypeScript to out/

npm run packageBump the patch version, compile, and write a .vsix

Running and debugging

Press F5. The Run Extension launch config compiles first (preLaunchTask: compile), then opens an Extension Development Host with the extension loaded. Edit src/, save, then press Ctrl+R in the host window to reload.

Two tasks are defined in .vscode/tasks.json: compile (the build task, Ctrl+Shift+B) and watch (the default background task, surfacing TypeScript errors in the Problems panel).

Tests

Tests live in test/ and use Vitest. They are pure unit tests — no VS Code host is needed, so they run in a second or two.

Nothing that imports vscode is unit-testable. Keep logic in modules that take plain values, and keep the VS Code API at the edges. That is why the anchor matching, comment scanning, parsing and reflow engines are all separate from their providers.

Packaging a release

npm run package

scripts/release.ps1 then does three things:

  1. Bumps the patch version in package.json — file only, no git tag
  2. Runs @vscode/vsce package, which triggers vscode:prepublish and compiles
  3. Writes the .vsix to dist/ and rewrites the version in every file that names it
Two files contain the VSIX filename. README.md and docs/articles/install.html both contain the literal kat-comment-studio-<version>.vsix. The release script string-replaces it. Keep that literal intact when editing either file, or the download links go stale — the script warns when it finds no match.

Commit the version bump and the new .vsix afterwards.

The documentation site

This site is plain static files under docs/, published by GitHub Pages from the main branch. There is no build step — push and it is live.

  • docs/index.html — the shell
  • docs/assets/manifest.json — the ordered topic list that drives the nav and the pager
  • docs/articles/<id>.html — one HTML fragment per topic, semantic markup only
  • docs/assets/docs.css, docs/assets/docs.js — styling and hash routing

To add a topic, drop a fragment in articles/ and add an entry to manifest.json. Headings get IDs and an on-this-page entry automatically; link to one with #/<article>/<heading-id>.

Preview locally with any static server, for example npx serve docs.
