Prefix Highlighting

Colors a comment based on the character it starts with, so alerts, questions and dead code stand apart at a glance. Modelled on Better Comments.

Prefixes

PrefixDarkLightUse
// !#FF2D00#CC0000Alerts and warnings
// ?#3498DB#2070B0Open questions
// *#98C379#008000Highlighted notes
// //#808080#999999Deprecated — rendered struck through
// -#505050#AAAAAADisabled or parked items
// >#C586C0#800080Quotes — rendered italic

Example

// ! Do not call this before Initialize() runs
// ? Should this retry, or fail fast?
// * The cache key must include the tenant id
// // legacyPath = ResolveOld(name);
// - Parked until the 2.0 migration
// > "Premature optimization is the root of all evil."

Which comments qualify

The prefix must be the first thing after the comment marker, followed by a space. Single-line markers are recognized generically, so this works with //, # (PowerShell, Python, YAML), ' (VB), and others — in any file type, not just the doc-comment languages.

String literals are skipped. Comment detection steps over string, template and character literals, so var s = "don't";, var url = "http://x"; and char c = 'a'; are read as code rather than as the start of a comment. Block comments and SQL -- are not prefix-highlighted.

Configuration

  • Turn it off entirely with enablePrefixHighlighting: false.
  • Recolor any prefix through colorOverrides — see the color keys.
