Comment Reflow

Rewraps XML doc comment blocks to a line width, without ever splitting an XML element. It runs when you leave a block you edited, when you paste into one, or on demand.

What reflow changes

  1. XML elements are never split — a <paramref> moves to the next line as a unit.
  2. Lines are wrapped to fit the resolved line width.
  3. A blank line directly after an opening tag such as <summary> is removed. A blank line you put between two elements is kept — that spacing reads as intentional.
  4. <summary> is always forced onto its own line.
  5. If a <summary> opens with a <para> but later content is left untagged, the loose content is wrapped in <para> elements as well, split on blank lines.
  6. <code> blocks are preserved verbatim and never reflowed.
  7. Block tags (<summary>, <remarks>, <param>, …) each wrap their content independently.
XML doc comments only. JSDoc /** */ blocks are never reflowed — see JSDoc / TSDoc.

No format-on-save integration. The extension does not register a document or range formatting provider, so it never competes with C# Dev Kit, OmniSharp, or Prettier. Use Reflow Comments in File instead.

Auto-reflow on edit exit

When you leave a doc comment block you edited, it is reflowed. This is the only moment the extension rewrites a comment you typed — nothing is reformatted while the caret is inside the block.

The reflow is held for autoCollapseDelay milliseconds (default 1000) so that reflow and auto-collapse happen together, instead of the text shifting while the block is still open. Move the caret back into the block before the delay elapses and the queued reflow is cancelled; it re-queues next time you leave.

The reflow is its own undo step, so Ctrl+Z right after leaving a comment reverts the reflow and keeps your text exactly as typed. Undo and redo never re-trigger a reflow.

Controlled by enableReflowOnCommentExit (default true).

Smart paste

Pasting into an XML doc comment block reflows the whole block — but only once the caret has left it. While you are still editing, nothing is reformatted, so paste-then-type never fights your cursor.

Controlled by enableReflowOnPaste (default true).

Line width

Resolved in this order, first match wins:

  1. max_line_length from the nearest .editorconfig for the file's directory
  2. the reflowLineLength setting (default 120)
